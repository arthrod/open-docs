# Fresh baseline, 2026-11-09 (after clearing `od_metrics_1`)

The 84 development rows were archived in
[`2026-11-09-dev-runs.md`](2026-11-09-dev-runs.md) and the table cleared. Then
every editor was loaded three times under the same conditions:

- Chrome (macOS, Apple silicon), the live val `https://open-docs.val.run`.
- **One editor per brand-new tab**, so every load reports its own JS heap
  (a second page in a tab inherits the renderer's heap; see README).
- **One load at a time**, never two editors at once (no CPU contention).
- Nothing else run on the page (no probes, no assistant turns).
- Order varied: round 1 and 3 canvas-editor → WordCraft, round 2 reversed.
- Browser HTTP cache not cleared (it can't be from the automation), so most
  loads are "warm" for the big files; canvas-editor, docen, folio and Plate
  loads still counted as cold by the 20 % transfer rule.
